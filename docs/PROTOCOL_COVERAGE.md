## 原文矛盾与采取的规则

- §3.2.12–14：MF501 标为 int64 但寄存器数量 2；跨度 4 个寄存器。ASCII 按 int64 访问，RTU 暂禁用，未擅自改成 4。
- §3.2.21：CURRENT 标为 uint16 / 1 寄存器，范围却到 900000000。ASCII 工程单位为原始值 /1000 A；RTU 暂禁用。
- §3.6.1 的 PTB/PTC 示例与 §3.2.9–10、指令表默认值相差 10 或 100 倍。按专门参数节：PTA /10^9，PTB /10^12，PTC /10^16；不使用 INQUIRE 示例作为默认配置写回。
- PTRP 的专门节示例为 2 kΩ，指令表和全面查询示例出现 1 kΩ；软件只显示真实读回，不向设备灌入任何默认值。
- POLA 的系数尾数按原文 99999999999999 → 9.9999999999999，即 /10^13；指数独立使用 POLEA，不把二者混成一个有舍入风险的浮点写入。
- §3.4.4 的 AUTOPID=2 明示预留；公开写入范围收窄至 0–1，读取仍可展示设备原始值。
- ADDRESS 原文配置 0–255，应用保留配置范围；连接 Modbus 站号只接受 1–247。ASCII 无设备地址，不适合多设备同时在线的总线。
- CRC 表头的“高字节/低字节”与示例叙述容易混淆；按正文说明与示例帧采用 CRC 低字节先传。
- INQUIRE 示例出现 TEC=215 且缺少分隔符，而 TEC 独立命令说明为型号枚举。客户端兼容缺失分隔符，型号保留原值，不推断为某型号。
- DATADEMAND=2 示例使用全角冒号属于文档排版；线上严格使用 ASCII。
- CHRATIO、STEADYIOB 仅见于批量返回，缺少正式可写定义；保留诊断原值。

## 参数提示

- `TCADJTEMP`：写入是外部温度输入，不是目标温度；需配合传感器保护配置。999999999 表示无传感器。
- `ENABLE`：0 关闭；1 开启
- `MODE`：0 制冷+加热；1 仅制冷；2 仅加热；3 手动电压百分比
- `PIDPOL`：0 正极性；1 反极性
- `PWMDUTY`：仅在 MODE=3 下手动控制。
- `AUTOPID`：0 关闭；1 自整定；文档值 2 为保留，不提供写入。
- `SPEED`：0 不限速
- `ONSENSOR`：1 启用；0 允许外部温度输入
- `POWERMODE`：0 记忆状态；1 上电开启；2 上电关闭
- `CURRENT`：协议 uint16 与范围矛盾，RTU 暂禁用。
- `POLYOMIAL`：0 NTC B；1 PT；2 Steinhart-Hart；3 MF501（协议原拼写）
- `POLA0`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA1`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA2`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA3`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA4`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA5`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA6`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `POLA7`：尾数 = 原始整数 / 10^13；最终系数 = 尾数 × 10^指数。
- `MF501A`：协议 int64 / 2 寄存器矛盾，RTU 暂禁用。
- `MF501B`：协议 int64 / 2 寄存器矛盾，RTU 暂禁用。
- `MF501C`：协议 int64 / 2 寄存器矛盾，RTU 暂禁用。
- `ADDRESS`：协议配置范围 0~255；Modbus 单播连接仅支持站号 1~247。写入后按新站号重连。
- `CONTMODE`：0 独立；1 温差；2 输出跟随；3 温差+跟随
- `BOUNDTABLEONE`：0 4800；1 9600；2 19200；3 38400；4 57600；5 115200；6 230400；7 460800。写入后重连。
- `BOUNDTABLETWO`：0 4800；1 9600；2 19200；3 38400；4 57600；5 115200；6 230400；7 460800。写入后重连。
- `OVERTTEMP`：0 继续输出；1 停止输出
- `FPWM`：0 0.5 Hz；1 1 Hz；2 10 Hz；3 100 Hz

## 2026-10-16 实机只读验证：207L / 固件原始代码 5007

通过 `/dev/ttyUSB0`、38400、ASCII 验证型号、固件、双通道温度/电阻/目标/使能/模式/输出、故障码，以及 INQUIRE、DATADEMAND 1/2。仅发送读取与查询命令，没有写入设备配置或开启输出。

实机差异与兼容：

- TEC 实际返回字符串 `207L`，并非文档中的数字枚举；保留字符串显示。
- 固件命令应答为 `OK:FPV=5007@`，支持 OK 后可选冒号；固件版本保留原始代码，不猜测分段。
- 应答结尾和 INQUIRE 子组之间带 NUL 字节；仅容忍帧边界的 NUL，不容忍数值字段内的异常字符。
- 通道 1 LIMITED 读回 100，而文档可写范围为 0–90。参数表显示真实读回值，常用输入不把 100 静默截成 90，仍保留文档写入范围；未尝试修改该值。

已通过真实 Qt 窗口、DeviceWorker、Client 的连续只读采样，两个通道使能均为 0、输出为 0、故障码为 0。此验证不代表实际加热、停止动作或温控精度已验证。新增实机格式回归后总计 23 项测试通过。
