# 上位机算法扩展

## 当前入口

“算法控制”位于“实时控制”之后。一次会话仅运行一个算法，可选通道 1 或 2。
首个 `ramp_pid` 直接写 MODE=3 / PWMDUTY，温度来自现有设备传感器。
它是上位机接管闭环，与保留设备 PID 的慢外环属于两种不同路径。

算法声明各参数是否支持运行中更新：斜坡 PID 的 P/I/D 系数与开关、微分滤波、斜坡速度、输出变化率、制动与过冲选项支持在线调节；方向、输出极性、温度边界与最大采样间隔启动后置灰。目标仍可回车更新。目标精度 0.01 °C，测量显示三位小数。
控制器初次采样以当前温度初始化斜坡参考，首个命令为零；随后按实际单调时间间隔计算。
斜坡目标、比例项、可选积分和测量微分构成 PID；测量微分做一阶滤波。
输出限幅、变化率限制和条件积分抑制饱和累积。禁用“允许过冲”启用预测制动，
按测量趋势提前限制朝目标方向的输出；制动优先于变化率限制，不是无过冲保证。
制热/制冷方向以热作用定义，再按“反转输出符号”映射 TEC 电气极性。
根据当前台面升温指令实际导致降温的反馈，默认启用反转：制热发送负输出，制冷发送正输出。
模拟器手动模式采用相同方向；更换接线后可取消该开关。此修改未自动写入正在运行的设备。

默认参数不能代替实物整定。开始前确认 TEC 极性、传感器位置、设备保护、电流和电压上限。
模拟器不代表真实热对象，也不能证明 0.01 °C 精度。算法参数、开关、目标和通道修改后自动保存在独立 YAML 中，切换算法及重启会恢复；控制器积分/滤波状态不恢复，启动仍需手动操作。

## 插件契约

`src/sensefuture/algorithms/__init__.py` 中的 ALGORITHMS 是显式注册表，不会扫描或执行外部未知文件。
新增算法实现 `TrackingController`：

- 构造函数接受配置字典。
- `reset()` 清除内部状态。
- `step(monotonic_s, temperature_c, target_c)` 返回带符号的电压百分比。
- `reference` 是当前内部跟踪参考，用于曲线显示。
- 不执行串口、Qt 或阻塞 I/O；状态仅在串口工作线程内访问。

注册一个 `Algorithm(key, name, description, fields, factory)`。
`Field` 支持数值范围/步进、布尔开关和枚举；Qt 表单自动生成。
不同算法可以定义不同的控制参数。当前工作线程要求共同的运行边界字段：
`min_temp`、`max_temp`、`max_gap`，分别限制温度和采样间隔。
输出上限 `limit` 由工作线程在启动时读取当前通道的设备 LIMITED 并注入控制器配置，不作为可编辑算法参数；不写入 LIMITED。允许继承 0–100% 的有效读回值（包括部分固件的 100%）；修改上限需停止算法，在实时控制写入后再启动。
注册项的 `validate()` 检查字段类型、范围及温度上下界；算法特殊约束应补充验证。
算法内部应处理方向、变化率及抗饱和；工作线程独立拒绝非有限或超过 limit 的输出。

PID 系数单位为 Kp (%/°C)、Ki (%/°C/s)、Kd (%·s/°C)，不等同于设备固件 KP/KI/KD 数值。

## 执行与停止

串口只能由 DeviceWorker 持有。GUI 提交 `host_start`、`host_target`、`host_stop` 操作，
通过 `algorithm_state` 接收启动、采样和停止状态。启动先验证设备，再依次写入：
ENABLE=0、MODE=3、PWMDUTY=0、TG、ENABLE=1，每次写入读回确认。
运行中拒绝其他写入，包括另一通道和全局参数，避免间接改变联动或串口配置。
分段计划运行时不能启动算法，算法运行时也不能启动分段计划。

每轮完整采样后计算一次输出，串行发送并读回，不排队积压多个控制命令。
采样耗时或相邻样本间隔超过 max_gap、设备故障、温度越界、MODE/TG/ENABLE 不符、
算法异常或通信异常时中止。停止先撤销控制器，再尝试关闭输出并置零；失败明确显示未确认。
切换算法和修改固定参数必须先停止；在线参数由控制线程校验并交给控制器 reconfigure，保留斜坡参考与采样时钟，关闭积分时清空积分。重新启动时重置内部状态；不自动恢复 PID、重连或继续控制。

关闭全部输出会清空排队操作并关闭两路；退出沿用同一关断路径。
已发送事务不能被抢占。串口故障、强制终止进程、操作系统挂起等情况下，
上位机不能保证关闭命令送达；协议未确认有通信失联看门狗，需设备或硬件保护。

算法页与实时页使用同一个物理观察组件；切换标签时将组件移至当前页，数据、通道显隐、窗口配置、CSV 状态和图形历史均保留。稳定性统计区也复用同一组件，并跟随当前页面选定通道。主图保留共同历史至主动清空或重新连接；算法参考按同一采样时刻附加到主图点线。输出图和 CSV 统一使用设备采样读回值，算法状态行显示该轮读回确认的输出命令。内部算法状态缓存保留最近 30,000 条，用于调试，不再维护独立绘图视图。
当前 CSV 不记录算法内部积分、滤波状态或斜坡参考，不能作为完整算法状态回放。

## 验证范围

自动测试覆盖控制器数值约束、模拟客户端、Qt 的启动/更新/停止、写入互斥、
启动保护条件失败、算法异常、全部关断，以及关断失败状态。
实机极性、实际采样率、关断可靠性、保护覆盖和精密跟踪性能尚待验证。

## 单算法入口和配置

每个算法对应一个模块，例如 `src/sensefuture/algorithms/ramp_pid.py`，其中包含实现类和 `PLUGIN` 元数据。
共享的 Field / Algorithm / TrackingController 放在 `base.py`。
新增模块后，在 `algorithms/__init__.py` 导入并按稳定 key 加入 ALGORITHMS；key 使用小写字母、数字及下划线。
Qt 页面按元数据加载表单。算法可通过 `configuration_factory(root, report)` 提供自己的参数存储；主程序不决定算法的文件名、格式或保存策略。返回对象支持 value / setValue / contains；未提供工厂时使用当前会话的内存参数。

配置根目录默认为 `$XDG_CONFIG_HOME/sensefuture`（通常 `~/.config/sensefuture`），可通过 SENSEFUTURE_CONFIG_DIR 覆盖。
全局偏好统一进入 global.yaml。当前 ramp_pid.py 的 open_configuration 自行管理 algorithms/ramp_pid.yaml，包含参数、target_c 和 channel，并自行迁移旧 ramp_pid.ini。其他算法可以使用不同文件布局、格式或存储方式；主程序仅转交参数变化。
字段新增时使用声明默认值；未知字段不加载到算法；无效数值回退默认值并记录日志，启动时继续做整体验证。
LIMITED 是启动时从设备注入的运行边界，不写进算法参数文件。
文件只存参数，不存输出使能或自动恢复运行的指令；打开应用只恢复界面。

启停使用单一 toggle，状态以工作线程确认结果为准；接管及关断期间禁止重复点击。停止请求发出后的旧运行通知不会恢复按钮；关断失败保持未确认状态并允许重试。

## 插件面板注册与在线参数

算法提供 `panel_factory=initialize_panel`，主程序创建空的 AlgorithmPanel 后调用工厂。
算法入口内自行组织 `panel.section(title)`、`panel.note(text)` 和 `panel.parameter(key)`，
注册的参数需与算法 Field 定义一致。内置参数支持小数、整数、开关、枚举和文本。
自定义控件使用 `panel.register(key, widget, getter, setter, signal)`，配置读写与运行状态统一绑定。
没有 panel_factory 的算法保留按 Field 顺序创建默认表单的兼容路径。

Field 的 `live=True` 表示算法承诺该参数支持在线更新；默认 False。
面板在运行中只启用 live 参数，接管/停止/关断失败期间禁止在线编辑。
控件提交值后保存至插件配置，将修改合并 100 ms 后通过 host_config 交给串口工作线程。
待确认控件暂时禁用；工作线程拒绝固定参数、未知字段、无效值与硬件 limit 覆盖，
再调用控制器的 `reconfigure(settings)`。实现应在校验成功后原子替换参数，不阻塞、不执行 I/O。
确认后恢复控件；拒绝时回填已应用值。修改不会重启控制器或抢占串口。

reconfigure 的 settings 包含继承的 limit，但插件不能通过在线参数修改它。
新的值在下一次控制采样计算时使用；在线调节速度仍受设备采样周期限制。
停止/全部关断清除未发送调参请求；UI 延迟收到旧运行通知不会取消关断。
