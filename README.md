# SenseFuture 温控工作台

uv 管理的 Python + PyQt6 桌面工程，面向 Linux。协议依据 `docs/RD105_SPEC_通讯协议_v1.3.0.pdf`（2026-01-12 修订），厂商 UI 截图作为布局参考。

## 启动

```sh
cd ~/code/sensefuture
uv sync --frozen
uv run sensefuture
```

无硬件预览：

```sh
uv run sensefuture --demo
```

本机已安装依赖并生成 `uv.lock`，`.python-version` 固定 Python 3.13。离线可执行 `uv sync --frozen --offline`。工程支持 Python 3.12 及以上；当前验证环境为 Python 3.13.3 / Qt 6.10。

## HiDPI 与字号

使用系统字体与 Qt 的 DPI 缩放，默认正文字号至少 14 pt。窗口右上角 A− / A+ 或字号输入框可调整 10–22 pt，并自动保存。Ctrl+加号 / Ctrl+减号调整，Ctrl+0 恢复默认。图表刻度、图例、日志和参数表同步放大；小窗口可滚动访问内容。重启程序即可使用新版界面。

## 第一阶段功能

- 双通道，ASCII 与 Modbus RTU 0x03 / 0x10，Linux 串口枚举、手动路径、站号和全部文档波特率。
- PID 参数区位于稳定性观察上方，支持当前通道的 P / I / D 读取、编辑与写后读回；切换通道同步显示。
- 右上角全部关断按钮按设备读回显示状态：红色可关断、黄色正在关闭、绿色全部已关闭、红色失败可重试；关断期间拦截新写入命令，避免随后重新开启输出。
- 当前通道输出使用醒目的单个切换按钮；橙色为已开启，蓝色为已关闭，写入期间显示等待并禁用重复操作，设备读回确认后才更新开关状态。
- 目标温度、设备 PID、输出使能、加热/制冷/手动模式、输出上限、手动输出、温变斜率与自整定。
- 完整参数表：62 个参数定义，覆盖传感器模型、NTC/PT/MF501、多项式 A0–A7 尾数/指数、保护、通道联动、通信与恢复出厂。显示工程单位，范围检查采用 Decimal，保留 64 位整数。
- INQUIRE 全面查询；DATADEMAND=1 与 =2；收发诊断、设备故障位解析。未知/保留字段保留原值，缺少正式定义的指令不猜测写入。
- 通过「通道 1：显示 / 隐藏」「通道 2：显示 / 隐藏」按钮，温度及目标曲线可随时独立显示或隐藏，不改变设备输出。主图跟踪全部历史，右键菜单可清空图形；下方输出百分比图和可选温度小图均默认跟踪最近 5 秒，各自旁边的 − / + 按钮可按 1 秒调整窗口（1–3600 秒），并自动记住设置。清空图形不清空 CSV 缓存、不中断记录或控温。
- 温度显示与刻度统一三位小数；常用设温、完整参数页温度写入与分段目标按 0.01 °C 检查，协议 API 和 CSV 仍保留原始精度。
- 温度/目标/输出曲线，默认最近 15 秒当前目标段的均值、标准差、峰峰值、最大绝对误差与 ±0.01 °C 带内比例。
- CSV 连续记录与当前缓存导出，记录 UTC 时间、单调时钟、通道、温度、目标、误差、输出百分比、电压（ASCII）、电阻、使能与错误码。时间戳标记上位机完成一轮采集的时间；设备无采样时间戳，通道间不是同时采样。无效温度留空。主图保留本次连接、清空图形以来的全部采样，时间轴自动覆盖全部历史；绘制使用峰值降采样。统计缓存保留最近 30,000 次采样，CSV 导出缓存保留最近 60,000 行；长时间实验请开启连续记录。
- 基础分段控温：到温后才累计连续保温时间，离开容差带重新计时，完成后保持最后目标和输出。
- 独立串口线程、有限队列、写后读回、超时/CRC 异常断开、无自动写入重试。关闭全部输出会清空排队操作并优先请求关闭已配置通道。

## 第一次连接设备

1. 选择真实串口（如 `/dev/ttyUSB0` 或稳定的 `/dev/serial/by-id/...`），匹配波特率、协议和站号。TTL 默认 38400，RS485 默认 9600，8N1；Modbus 默认站号 1。
2. 点击连接后软件仅查询，不会主动打开输出或批量覆盖参数。查看设备型号、固件、传感器温度、故障与保护配置。
3. 先设置合适的设备保护阈值和输出上限，再明确写入目标、模式和使能。完整参数页的通道与实时页的通道选择同步。
4. 开启连续记录，观察多个温度点的稳定过程。采样周期是期望值，实际周期受波特率和通信事务数量影响，以记录的时间戳为准。

串口权限不足时，需要当前用户拥有设备访问权限；应用不会自行修改系统组或权限。ASCII 没有站号字段，因此不要在多设备总线上同时发送 ASCII 请求。

关闭串口、取消计划或断线不会保证设备停止加热。窗口退出不弹确认框，自动清空待执行命令、关闭两路输出并等待设备读回确认，然后断开串口退出；关闭期间禁止重复操作。若未确认关闭，保留窗口并显示状态，不弹对话框。通信中断时上位机无法保证送达关闭命令，设备自身保护仍需有效。软件的“关闭全部输出”是串口命令，不是硬件急停。

## 协议边界

详见 `docs/PROTOCOL_COVERAGE.md`，含所有映射、缩放及原协议中的矛盾。

- MF501A/B/C：原文 int64 但写 2 个寄存器，ASCII 可读写，RTU 暂禁用，等待厂家确认。
- CURRENT：原文 uint16 / 1 寄存器但范围到 900000000，ASCII 可读，RTU 暂禁用。
- DATADEMAND=1 的 PWM 没有给出非零值的换算示例。诊断显示原始值；主曲线使用有明确比例的 PWMDUTY，不对 PWM 静默假设单位。
- AUTOPID=2 是保留功能，不提供写入。CHRATIO / STEADYIOB 仅见于 INQUIRE 示例，无正式写入和寄存器定义，不伪造支持。
- 连接配置、地址、恢复出厂写入后主动结束会话，需要按设备新配置重连；若固件立即重启或改波特率而没有应答，软件会报告状态未知，不重试。
- 应答没有事务 ID。发生超时、CRC 或帧错误时关闭连接，避免将迟到帧误认为下次请求成功。
- 停止输出无法抢占已发送事务；INQUIRE 在低波特率下可能需要数秒。需要硬实时停止时必须依靠设备或硬件。

## 0.01 °C 与第二阶段

协议通信分辨率为 0.00001 °C；界面温度显示为 0.001 °C，人工设温步进为 0.01 °C，这些格式不代表绝对测量准确度、稳定度或重复性达到 0.01 °C。界面中的 ±0.01 °C 统计是设备读数相对目标的观察结果；模拟模式也不能证明真实精度。

“实时控制”之后新增“算法控制”页，可选择算法和独立通道。首个算法为 **斜坡 PID · v1**：上位机通过 MODE=3 / PWMDUTY 直接调节 TEC 电压百分比，不使用设备温度 PID。支持制热/制冷方向、输出反转、允许过冲、P/I/D 开关与系数、微分滤波、目标斜坡、继承设备输出上限与变化率、预测制动、温度边界及最大采样间隔。每个算法通过自己的 panel_factory 初始化左侧面板，注册参数控件、分组和说明；可使用默认数值/开关/枚举/文本控件，也可注册自定义控件。

参数按算法声明决定运行中是否可调：斜坡 PID 的 P/I/D 系数与开关、滤波、斜坡速度、输出变化率、制动时间和允许过冲支持运行中更新；方向、极性和温度/采样边界运行时置灰。修改保存后由控制线程校验并确认，下一控制采样使用新值；失败回填已生效值。单一 toggle 按钮切换接管/停止：未运行蓝色、运行橙色，接管/停止期间禁用并等待设备确认，关断失败显示重试；运行中可用目标输入框回车或“更新跟踪目标”调整目标。两页直接复用同一观察组件，包含双通道温度卡片、全部历史主图、输出和近期温度小图、通道显隐、时间窗口、CSV 工具及稳定性统计。切换页面不重建图形、不清空历史；算法斜坡参考以点线叠加在主图上，正常启动算法也不清空共同历史。输出图统一显示设备采样读回值，算法状态行另外显示已发送并读回确认的命令。稳定性统计随当前页面所选控制通道切换。启动不自动调参；输出上限继承实时控制已写入设备的 LIMITED 设置，算法不会修改该硬件参数；其余参数只是调试起点，可能无法达到给定目标。

启动会检查传感器、故障、温度边界、独立通道模式及 ONSENSOR=1，读取并继承设备 LIMITED 作为算法饱和边界；随后关闭通道输出、切换手动模式、置零、写入目标，再使能。运行期间其他手动写入和分段计划被拦截。正常停止关闭当前通道输出并置零，保留手动模式，不自动恢复 PID。数据无效、超出边界、模式/目标/使能改变、采样间隔异常、算法错误或通信错误都会中止算法并尝试关断；实际通信故障可能使关断无法送达。全部关断及窗口退出继续关闭两路输出。

“禁止过冲”仅启用预测制动，不保证实际无过冲。采样和控制在串口工作线程中执行，周期受通信耗时限制，无硬实时保证。当前仅做模拟验证，没有在真实 TEC 上启用该算法。扩展约定见 `docs/ALGORITHMS.md`；外部参考温度计、级联控制与验收路线见 `docs/SECOND_STAGE.md`。


当前 66 项测试通过。测试覆盖协议示例、分片、负温度、64 位读数、参数访问、写回校验、CRC/异常、模拟通信、真实 pyserial 后端的伪终端、Qt 连接/记录/无效传感器与分段计划，以及上位机 PID、斜坡、限幅、抗饱和、方向切换、制动、接管互斥、目标更新、故障停止与关断确认。已在 207L / 固件原始代码 5007 上验证 ASCII 只读连接、状态、批量查询和 Qt 连续采样；没有开启加热或写入设备配置。尚未验证 Modbus 实机、硬件安全动作、设备实际持久化或任何温控精度指标。

## 工程结构

```text
src/sensefuture/
  catalog.py      参数映射与工程单位
  protocol.py     ASCII / Modbus 编解码与校验
  device.py       串口事务与模拟设备
  worker.py       Qt I/O 线程与命令调度
  app.py          控件、实时观察、记录与基础分段计划
  config.py       全局 YAML、原子保存及配置工具
  algorithm_panel.py 插件控件注册、配置绑定与运行状态
  algorithms/
    __init__.py   显式算法注册
    base.py       参数声明和算法契约
    ramp_pid.py   首个算法独立入口、实现及参数定义
  control.py      后续级联控制的提案接口（当前未执行）
tests/            自动测试
docs/             原始协议、覆盖说明、下一阶段设计
```

目标温度输入框不带单位（单位标在标签上），输入后按回车即可写入。稳定性观察窗口默认 15 秒，可用旁边的 − / + 调整并自动保存；统计仅包含当前目标温度的连续数据段。

稳定性观察以主温度图内的浮窗显示，拖动标题可移动，位置自动保存；时间加减按钮保留在浮窗内。两个控制页继续共享该浮窗，近期温度小图的位置不变。

## 配置文件

默认使用 `$XDG_CONFIG_HOME/sensefuture/`，未设置 XDG 时通常为 `~/.config/sensefuture/`：

```text
sensefuture/
  global.yaml                 界面、串口和观察设置
  algorithms/
    ramp_pid.yaml             首个算法的参数、开关、目标温度和通道
```

修改设置后立即保存，退出时保存窗口位置。全局文件记录串口、波特率、协议、站号、读取周期、字号、控制通道、曲线显隐、各观察窗口长度、浮窗位置和上次所选算法。算法自行选择配置后端；当前斜坡 PID 管理独立 YAML 文件，切换算法或重启会恢复各自参数；内部积分/滤波状态、运行状态与输出使能不保存恢复。硬件 PID、保护阈值和 LIMITED 仍以设备读回为准，不会从软件配置自动写回。

首次使用时，将旧 global.ini 或 Qt 设置迁入 global.yaml；斜坡 PID 自行将旧 ramp_pid.ini 迁入 ramp_pid.yaml。保留旧文件作为迁移来源，后续只更新 YAML。保存采用临时文件和原子替换，失败会写入诊断日志。可用 `SENSEFUTURE_CONFIG_DIR=/path/to/config uv run sensefuture` 指定另一套配置目录。配置文件不会触发自动连接、启动算法或开启输出。
