# SenseFuture 温控工作台

uv 管理的 Python + PyQt6 桌面工程，面向 Linux。协议依据 `docs/RD105_SPEC_通讯协议_v1.3.0.pdf`（2026-01-12 修订），厂商 UI 截图作为布局参考。

## 启动

```sh
cd ~/code/sensefuture
uv sync --frozen
uv run sensefuture
```

无硬件预览：

```sh
uv run sensefuture --demo
```

本机已安装依赖并生成 `uv.lock`，`.python-version` 固定 Python 3.13。离线可执行 `uv sync --frozen --offline`。工程支持 Python 3.12 及以上；当前验证环境为 Python 3.13.3 / Qt 6.10。

## HiDPI 与字号

使用系统字体与 Qt 的 DPI 缩放，默认正文字号至少 14 pt。窗口右上角 A− / A+ 或字号输入框可调整 10–22 pt，并自动保存。Ctrl+加号 / Ctrl+减号调整，Ctrl+0 恢复默认。图表刻度、图例、日志和参数表同步放大；小窗口可滚动访问内容。重启程序即可使用新版界面。

## 第一阶段功能

- 单/双通道，ASCII 与 Modbus RTU 0x03 / 0x10，Linux 串口枚举、手动路径、站号和全部文档波特率。
- 目标温度、设备 PID、输出使能、加热/制冷/手动模式、输出上限、手动输出、温变斜率与自整定。
- 完整参数表：62 个参数定义，覆盖传感器模型、NTC/PT/MF501、多项式 A0–A7 尾数/指数、保护、通道联动、通信与恢复出厂。显示工程单位，范围检查采用 Decimal，保留 64 位整数。
- INQUIRE 全面查询；DATADEMAND=1 与 =2；收发诊断、设备故障位解析。未知/保留字段保留原值，缺少正式定义的指令不猜测写入。
- 温度/目标/输出曲线，最近 60 秒当前目标段的均值、标准差、峰峰值、最大绝对误差与 ±0.01 °C 带内比例。
- CSV 连续记录与当前缓存导出，记录 UTC 时间、单调时钟、通道、温度、目标、误差、输出百分比、电压（ASCII）、电阻、使能与错误码。时间戳标记上位机完成一轮采集的时间；设备无采样时间戳，通道间不是同时采样。无效温度留空。内存保留最近 30,000 次采样；长时间实验请开启连续记录。
- 基础分段控温：到温后才累计连续保温时间，离开容差带重新计时，完成后保持最后目标和输出。
- 独立串口线程、有限队列、写后读回、超时/CRC 异常断开、无自动写入重试。关闭全部输出会清空排队操作并优先请求关闭已配置通道。

## 第一次连接设备

1. 选择真实串口（如 `/dev/ttyUSB0` 或稳定的 `/dev/serial/by-id/...`），匹配波特率、协议和实际通道数量。TTL 默认 38400，RS485 默认 9600，8N1；Modbus 默认站号 1。
2. 点击连接后软件仅查询，不会主动打开输出或批量覆盖参数。查看设备型号、固件、传感器温度、故障与保护配置。
3. 先设置合适的设备保护阈值和输出上限，再明确写入目标、模式和使能。完整参数页的通道与实时页的通道选择同步。
4. 开启连续记录，观察多个温度点的稳定过程。采样周期是期望值，实际周期受波特率和通信事务数量影响，以记录的时间戳为准。

串口权限不足时，需要当前用户拥有设备访问权限；应用不会自行修改系统组或权限。ASCII 没有站号字段，因此不要在多设备总线上同时发送 ASCII 请求。

关闭串口、取消计划或断线不会保证设备停止加热。窗口退出可选择先关闭输出并等待设备读回确认。通信中断时上位机无法保证送达关闭命令，设备自身保护仍需有效。软件的“关闭全部输出”是串口命令，不是硬件急停。

## 协议边界

详见 `docs/PROTOCOL_COVERAGE.md`，含所有映射、缩放及原协议中的矛盾。

- MF501A/B/C：原文 int64 但写 2 个寄存器，ASCII 可读写，RTU 暂禁用，等待厂家确认。
- CURRENT：原文 uint16 / 1 寄存器但范围到 900000000，ASCII 可读，RTU 暂禁用。
- DATADEMAND=1 的 PWM 没有给出非零值的换算示例。诊断显示原始值；主曲线使用有明确比例的 PWMDUTY，不对 PWM 静默假设单位。
- AUTOPID=2 是保留功能，不提供写入。CHRATIO / STEADYIOB 仅见于 INQUIRE 示例，无正式写入和寄存器定义，不伪造支持。
- 连接配置、地址、恢复出厂写入后主动结束会话，需要按设备新配置重连；若固件立即重启或改波特率而没有应答，软件会报告状态未知，不重试。
- 应答没有事务 ID。发生超时、CRC 或帧错误时关闭连接，避免将迟到帧误认为下次请求成功。
- 停止输出无法抢占已发送事务；INQUIRE 在低波特率下可能需要数秒。需要硬实时停止时必须依靠设备或硬件。

## 0.01 °C 与第二阶段

通信/显示分辨率为 0.00001 °C，不代表绝对测量准确度、稳定度或重复性达到 0.01 °C。界面中的 ±0.01 °C 统计是设备读数相对目标的观察结果；模拟模式也不能证明真实精度。

当前完全使用设备固件控制回路，未启用上位机 PID。`src/sensefuture/control.py` 提供测量和控制提案接口，为外部标准温度计、级联控制、目标微调和增益调度保留边界。具体实施路线与验收见 `docs/SECOND_STAGE.md`。

## 验证

```sh
uv run python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen uv run sensefuture --demo --screenshot /tmp/sensefuture.png
```

当前 23 项测试通过。测试覆盖协议示例、分片、负温度、64 位读数、参数访问、写回校验、CRC/异常、模拟通信、真实 pyserial 后端的伪终端、Qt 连接/记录/无效传感器与分段计划。已在 207L / 固件原始代码 5007 上验证 ASCII 只读连接、状态、批量查询和 Qt 连续采样；没有开启加热或写入设备配置。尚未验证 Modbus 实机、硬件安全动作、设备实际持久化或任何温控精度指标。

## 工程结构

```text
src/sensefuture/
  catalog.py      参数映射与工程单位
  protocol.py     ASCII / Modbus 编解码与校验
  device.py       串口事务与模拟设备
  worker.py       Qt I/O 线程与命令调度
  app.py          控件、实时观察、记录与基础分段计划
  control.py      第二阶段策略接口（当前未执行）
tests/            自动测试
docs/             原始协议、覆盖说明、下一阶段设计
```
